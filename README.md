# Hero's Hour Build Calculator

A theorycraft sandbox for **Hero's Hour** hero builds — pick a hero, equip artifacts on a paperdoll,
tune primary stats, and see the resulting stats and army-wide buffs. Vanilla HTML/CSS/JS, deployable
as static files on GitHub Pages.

## Quick start
```sh
# 1. copy the sprite frames the SPA uses out of the sibling ../_hh_extract datamine
node build-assets.mjs
# 2. compile data → data.js (runs data-hygiene guardrails; --strict promotes warnings to errors)
node build-data.mjs
# 3. preview (LAN-accessible for real phone testing) — stop it (Ctrl+C) when done
node tools/serve.mjs 8080
```
Then open the printed URL. `index.html` loads `data.js` (→ `window.HH_DATA`) then `app.js`.

## Layout
```
hh-build-calc/
├── index.html          # entry; loads data.js then app.js
├── styles.css          # mobile-first, palette in :root variables (sampled from game UI)
├── app.js              # build-first UI + overlay selectors + stat/xref logic
├── data.js             # GENERATED by build-data.mjs — do not edit
├── build-data.mjs      # ../_hh_extract → data/*.json + data.js (+ hygiene guardrails)
├── build-assets.mjs    # ../_hh_extract sprites → assets/{heroes,artifacts,classes,factions}
├── data/               # shipped JSON subset (generated)
├── assets/             # shipped sprite frames (generated)
├── tools/serve.mjs     # LAN preview server
├── SPEC_PLAN.md · WIKI_CONTEXT.md · Progress.md   # planning + cross-session context
```

## Data
Compiled from the sibling **`../_hh_extract`** datamine (not shipped). See `WIKI_CONTEXT.md` for the
source→ship mapping and how to regenerate. Data is an **extract, not a verified golden dataset** —
decompiled but not hand-checked.

## Deploy (later)
Everything is static and `data.js` is committed, so deploy = push to GitHub and enable Pages on the
branch root. The Cloudflare Web Analytics beacon in `index.html` ships **commented out** — uncomment
it only at public release. No build action required.
